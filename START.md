# START — вход в проект (роутер по ролям)

> Ты в проекте на скелете **ProjectStarter**. Этот файл — роутер: определи, ЧТО ты делаешь,
> и иди по СВОЕЙ ветке. Читай только свою полосу — чужую не грузи (разгрузка, не наполнение).
> Маркеры скелета: папки `_VISION/`, `_Plan/`, `_map/`.

## Универсальные правила (коротко)

- Правишь `.py` → в ТОМ ЖЕ заходе обнови его карточку `_map/cards/<file>.py.md`.
- Прогресс — аппендом в хвост `_Plan/TRACKER.md` (`✅ … → следующий …`); читать только ХВОСТ.
- Адрес узла = имя файла: `<координаты-через-«-»>__<slug>.md` (напр. `Plan01-Task03__extract.md`).
  Разбор: `split("__")[0].split("-")`. Теги: `Plan` · `Task` · `Context` · `Vision` (`Design` — резерв).

## Куда идти — три ветки

### 1. Картирование — «сделать проект работаемым»
Код есть, а карты нет. Построй карту заголовков + карточки в `_map/cards/`.
Тянет **локальный агент**: долго, но верно. → методика в `_map/WORKFLOW.md`.

### 2. Планирование — «как должно работать / что делать» (сильная LLM + человек)
- **Вижен** — описать, КАК система должна работать → `_VISION/`. Карточки обычно УЖЕ есть
  (построены Картированием) — опирайся на них; в чужом проекте они точно есть.
- **Планы** — большие/локальные планы под вижен, обсуждая с юзером → `_Plan/plans/PlanNN__slug.md`.

### 3. Исполнение — «делать таск» (любой грейд)
Возьми таск: из явного слова юзера, иначе — **хвост `_Plan/TRACKER.md`** («где закончили»).
Прочитай ТОЛЬКО его `Plan` + `Context`, ныряй в конкретные файлы, делай.
Оборвалось → хвост TRACKER + файл таска + `git status` → продолжить/откатить.
