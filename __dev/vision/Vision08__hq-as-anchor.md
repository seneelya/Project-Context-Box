# Vision08 — `__HQ` как самостоятельная точка отсчёта («мозги» отдельно от исходников)

> **Замысел (intent), не механика.** Инварианты скелета — `Vision01__project-starter.md`. Текущая
> конвенция путей/корня/флагов тулов — `__HQ/tools/__dev/vision/Vision01__path-and-flag-conventions.md`
> (этот вижен её ДОПОЛНЯЕТ и в двух местах сознательно ПЕРЕСМАТРИВАЕТ — см. §5).
> Номер 08 — сквозной с `__HQ/tools/__dev/vision/` (там до Vision07), чтобы адрес был однозначен
> по обоим репо. План исполнения — `__dev/plans/done/Plan07__hq-anchor-paths.md`.

## 1. Проблема (реальный продакшен, не гипотеза)

Первый деплой скелета в **чужой** проект, который мы ведём как свой форк: `y:\SRC\llama.cpp_mix\`
(клон `ggml-org/llama.cpp`, работа в ветке `mix`, цель — сборка CUDA+Vulkan и микс-вычисления).

- В форк **не должно попасть ни одного нашего файла** — `git diff upstream/master` обязан
  показывать чистый код, иначе нельзя ни ребейзиться, ни отдавать upstream.
- Но нашему слою **тоже нужен git**: карточки, планы, recon — это знание, его коммитят часто.
- Значит: всё наше — внутри **одного** каталога `__HQ`, у которого **свой** git, а в git llama.cpp
  он скрыт через `.git/info/exclude`. Снаружи — только исходники и их git.
- Агент **стартует вне проекта** (например, в `y:\SRC\`), чтобы харнес не подхватил автоматом
  чужие `AGENTS.md`/`CLAUDE.md` upstream'а. Вход — явная команда оператора:
  «читай `y:\SRC\llama.cpp_mix\__HQ\START.md`».

Скелет сегодня этого не умеет, потому что **молча смешивает два разных корня**:

| что | сейчас считается от | где зашито |
|---|---|---|
| карточки `__map/` | `PROJECT_ROOT/__map` | 5 card-тулов, `root / "__map"` |
| логи тулов | `PROJECT_ROOT` + `LOG_DIR` | `CONFIG__TOOLS.LOG_DIR = "__HQ/tools/_logs"` |
| конфиг целевого проекта | `root/__HQ/tools/CONFIG__TOOLS.py` | `graph_from_cards.load_config_at` |
| sanity-check корня | «корень обязан быть предком тула» | `resolve_project_root` и копии |
| свежесть карточек | один git на корень | `check_cards_freshness` |
| точка входа | `START.md` в корне проекта | `deploy_hq.py`, доки |

Пока `__HQ` всегда лежал в корне исходников, разница была не видна. Теперь видна.

## 2. Модель: два корня, у каждого своя роль

- **Корень исходников — `PROJECT_ROOT`.** Код, который изучаем. Задаётся в конфиге **абсолютно**
  (пишет `deploy_hq.py`). ID карточки = путь исходника **относительно него** — не меняется.
- **Корень штаба — `HQ`.** Всё НАШЕ: карточки, логи, планы, recon, тулы, `START.md`. Тул **всегда
  знает свой `HQ` сам** — это родитель его собственной папки (`<HQ>/tools/<tool>.py`). Не читается
  из конфига и не зависит ни от cwd, ни от `PROJECT_ROOT`.

Обычная раскладка — `HQ` лежит внутри исходников (`<src>/__HQ`), но это **не требование**: штаб
может лежать где угодно, `PROJECT_ROOT` просто указывает на исходники.

```
y:\SRC\                         ← тут стартует агент (cwd — не важен)
  llama.cpp_mix\                ← PROJECT_ROOT, git llama.cpp (ветка mix)
    ggml\ src\ tools\server\ …
    __HQ\                       ← HQ, свой git, скрыт .git/info/exclude
      START.md                  ← вход (открывается по полному пути)
      CONTEXT_RESTORE.md
      __map\                    ← MAP_DIR (два подчёркивания остаются)
      plans\ recon\ docs\ DECISIONS.md TRACKER.md …
      tools\  CONFIG__TOOLS.py  _logs\
```

## 3. Правила

1. **Наши пути — от `HQ`.** `MAP_DIR` и `LOG_DIR` в конфиге задаются относительно `HQ` (абсолютный
   путь — тоже можно). Шаблонные значения: `MAP_DIR = "__map"` → `<HQ>/__map`,
   `LOG_DIR = "tools/_logs"` → `<HQ>/tools/_logs`. Якорь на `HQ` снимает класс багов «удвоенного
   пути» (`__HQ/tools/__HQ/tools/_logs`, 2026-09-14), который рождается у якоря на `PROJECT_ROOT`.
   Заодно закрывает запрос `__HQ/tools/__dev/Requests/logs_default_path.md` («логи не в папку
   проекта») — логи лежат у тула, в штабе, а не в исходниках.
2. **Явное всегда главнее конфига.** Конфиг даёт только умолчания. Работа одним штабом по разным
   местам полными путями (`get_codeblock --file <abs>`, `make_interface_card --project-root <чужой>`)
   **обязана остаться как есть**:
   - корень пришёл из конфига (флаг не задан) → карточки в `MAP_DIR` конфига;
   - корень задан явно (`--project-root <путь>`) → `MAP_DIR` конфига **НЕ применяется** (иначе
     карточки чужого проекта лягут в нашу карту — ID относительны корню, будет каша); для явного
     корня — как сейчас: `<корень>/__map` по умолчанию, или явный `--cards-dir` / `--out`;
   - `--cards-dir` — у **всех** card-тулов, включая штемпель (сейчас у него только `--out`).
3. **Нет конфига / нет `PROJECT_ROOT` → явный отказ**, а не тихий откат на cwd. При старте из
   `y:\SRC\` откат на cwd = работа над всем `SRC`. (Только для неявной ветки card-тулов; generic-тулы
   конфиг молча не читают вообще — см. §5.)
4. **Конфиг — свой.** Неявная ветка берёт конфиг **своего** `HQ` (соседний с тулом). Явный чужой
   `--project-root R` — как REQ-007: конфиг `R/__HQ/tools/CONFIG__TOOLS.py`, если он есть (легаси-
   раскладка), иначе встроенные умолчания.
5. **Свежесть — каждый файл у своего git.** Исходник спрашиваем у git исходников, карточку — у того
   git, где она лежит (`git -C <папка карточки>` сам находит ближайший `.git` → для `__HQ/__map/…`
   это git штаба). `%ct` — часы, не номер коммита, поэтому сравнение между репо осмысленно. Сторона
   без git → её mtime. Режим выбирается **попарно**, а не один на весь прогон. Работает на всех
   трёх раскладках: один git (memohood), два (llama.cpp_mix), штаб без git.
6. **Вход — внутри штаба, снаружи НИЧЕГО.** `START.md`, `CONTEXT_RESTORE.md`, `RITUAL__session_end.md`,
   `RULE_sessionRestore.md` живут в `__HQ/`; моста в корне (`AGENTS.md`) нет ни в своих, ни в чужих
   проектах — везде один путь (решение владельца 2026-09-29). `__HQ/…` в доках = папка штаба;
   абсолютных путей в `START.md` нет (он template-owned): штаб агент знает по пути, которым открыл
   `START.md`, исходники — `PROJECT_ROOT` конфига.

## 4. Совместимость

- Проект без `MAP_DIR` в конфиге (memohood, hermes-filetools) → **старое поведение**
  `PROJECT_ROOT/__map`. Ничего не ломается.
- `CONFIG_SCHEMA_VERSION` 1 → 2; `deploy_hq.py` сам покажет старым проектам `STALE-CONFIG`.
- Решение «`__map` на верхнем уровне проекта» (`__dev/DECISIONS.md`) пересматривается: `__map` —
  данные штаба, по умолчанию `<HQ>/__map`; легаси-раскладка остаётся валидной.

## 5. Что пересматриваем в `Vision01__path-and-flag-conventions.md` (tools) — и что нет

- **ПЕРЕСМОТР: sanity-check «корень обязан быть предком папки тула».** Он предполагал, что штаб
  всегда в корне. Теперь штаб вне исходников — нормальный случай, проверка его ложно отвергает.
  Угроза, от которой он защищал (REQ-002-C — протухший/чужой конфиг), уже закрыта тем, что
  `deploy_hq --init` пишет реальный путь, а конфиг теперь берётся из своего `HQ`. Взамен — «корень
  существует и это папка», иначе отказ.
- **ПЕРЕСМОТР (узко): «без общего модуля-хелпера».** Новый модуль не вводим — резолвер `MAP_DIR`
  кладём в `graph_from_cards.py` рядом с уже общим `resolve_project_root`: все пять card-тулов УЖЕ
  импортируют из `graph_from_cards` (штемпель — `load_config_at`, бандл — `build_graph`), новой
  зависимости не появляется. Generic-тулы не трогаем.
- **ПЕРЕСМОТР: generic-тулы (`get_codeblock`, `find_code_usage`, `show_pyfile_api`) — относительный
  `--file` сначала от `PROJECT_ROOT` конфига.** Агент стартует вне проекта; писать каждый раз
  длинный абсолютный путь — невыносимо (решение владельца, 2026-09-29). Правило:
  - абсолютный путь — как есть;
  - относительный → сначала `PROJECT_ROOT` (явный `--project-root` > конфиг), не нашли → cwd;
  - нашёлся в ОБОИХ и это разные файлы → берём от `PROJECT_ROOT` + одна строка-предупреждение;
  - открыли не от cwd → в заголовке `#File:` полный путь (агент видит, что открыто).
  Угроза REQ-002 (тихая склейка в чужой существующий файл) закрыта предупреждением о двойном
  совпадении и полным путём в заголовке; сам кейс REQ-002 (`../../x.py` из `__HQ/tools/`) уходит за
  пределы корня, не существует → откат на cwd → верный файл. Конфига нет → просто cwd, как раньше.

## 6. Non-goals

- Не переименовываем `__map` (два подчёркивания остаются) и `--project-root`.
- Не делаем «штаб на несколько проектов» — один штаб = один `PROJECT_ROOT` по умолчанию;
  чужие места — только явными путями.
- Не переносим сейчас в шаблон-доки то, что не проверено вживую: сначала код + проверка на
  `llama.cpp_mix`, потом раскладка/доки/деплой (Plan07, этапы A → B).
