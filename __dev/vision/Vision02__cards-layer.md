# Vision02 — слой над карточками: «вторая компиляция»

> **Замысел (intent), не механика.** Общие правила скелета и инварианты — в `Vision01__project-starter.md`
> (читай его первым: любая фича здесь меряется теми инвариантами). Формат самой карточки и как её
> делают — `__HQ/guides/Guide__MakeCard.md`. Здесь — ЗАЧЕМ нужен программный слой над карточками и из чего
> он состоит.

## Философия — две ступени компиляции, а не «монстр»

Карточка — это уже **компиляция файла**: что экспортирует, интерфейсы, что импортирует, как работает.
Недостающий уровень — **компиляция связей МЕЖДУ карточками**: кто узел, кто лист, где тупик, как
течёт зависимость. Это «взлёт над проектом» — ещё одна абстракция, видимая **без чтения всех файлов**.

Обе ступени намеренно **lossy** и **дёшевы для чтения**. Это противоположность лосслес граф-БД по
коду (типа codebase-memory): та тратит всю инженерию — tree-sitter/LSP/БД/демон — чтобы добыть
структуру из сырого кода, и заставляет агента собирать картину из осколков многими запросами. У нас
структура **уже** лежит в карточках, аккуратно и на любом языке. Значит мы берём ~тот же профит
(топология + сборка контекста) за **1% сложности** — при одном условии: **формат карточки достаточно
жёсткий, чтобы парситься без ЛЛМ.**

## Что это даёт потребителю

- **Взлёт над** — один тонкий артефакт-карта грузится в контекст один раз; `impact` / `chain` /
  `layers` агент выводит **в уме**, отдельные тулы под это не нужны.
- **Экономия вызовов** — `bundle` собирает нужные карточки в один блок вместо 5–10 `read`.
- **Карта двухслойна.** Тонкий индекс (имя + summary + рёбра) — всегда в контексте. Толстый слой
  (API/объекты/импорты) — не держим в голове, тянем **по требованию** через `bundle`.

Артефакт-карта — **плоский текст** (агенту нечего парсить, грепается, чисто диффается в git).
Mermaid — вторичный рендер **для человека** по требованию, не основной формат.

## Фундамент — строгий формат-контракт карточки

Всё стоит на одном: **фиксированные имена секций + обязательное присутствие всех полей** (пусто =
прочерк / `- none -`, но поле есть). Тогда парсер никогда не встречает «секция пропущена / может её
нет» — присутствие гарантировано, пустота выражена явно. Это убирает половину хрупкости без сложности.
YAML-заголовок **не вводим** — дублировал бы данные тела (рассинхрон) и хрупок для слабого автора;
строгость даёт не YAML, а фиксированные секции markdown.

## NOW — эта итерация (дёшево, детерминированно)

1. **Формат-контракт карточки** — зафиксировать секции и обязательное присутствие полей. Сразу
   законтрактовать зону **`## Doc links`** (`- none -` пока пусто) — ссылки на документацию проекта /
   номера тасок; на реальном проекте (где «в доке одно, а работает другое») это ценно.
2. **Починить make-скил** (`Guide__MakeCard.md`) под контракт. Добавить правило:
   **карточка уже есть → прочитать и исправить по коду и схеме** (правильная схема — в задаче,
   карточка — объект обработки), чтобы агент не пугался существующего файла.
3. **Валидатор на стороне создателя** — программный пакет + починенный `Guide__AuditCards.md`: проверяет
   структуру по контракту и **coverage/сироты** (файлы без карточек), сразу говорит локальному автору
   «тут ошибся, переделай».
4. **`rebuild_graph`** → тонкий индекс топологии плоским текстом (листья = 0 внутр. deps; точки входа
   = макс. dependents — выводимо из рёбер).
5. **`bundle <file>`** → карточка цели + API её зависимостей одним блоком.
6. **Свод ⚠️ discrepancies** — реестр «мин» со всех карточек; ключевое при **исследовании незнакомого
   проекта**.
7. **Токен-оптимизация вывода `check_cards_freshness`** — убрать полосы `===` и двойные таймстемпы;
   отставание — числом; добавить **коммиты, тронувшие исходник после даты карточки** (агент сразу
   видит, что смотреть).
8. **Причёсывалка `git`** — фильтр, снимающий визуальный/токенный шум вывода git для чтения агентом.

## FUTURE — за гейтами (не сейчас; строим, только когда оправдал реальный масштаб/боль)

- **Структурный слайсер** «номер строки → диапазон объемлющего top-level объекта» (по отступам/скобкам).
  **Stateless**, без демона; derived-кэш-БД — только если *замерили*, что перепарс дорог. Векторов не
  требует → **идёт раньше них**. Закрывает частую задачу «дай весь объект, в котором застрял вызов».
- **Векторный ретрив.** Правило «у объектов **обязателен докстринг**» → вектор по докстрингу →
  ретрив обретает СМЫСЛ. Тёплое хранилище (БД + опц. демон) нужно **только здесь**. Транспорт к
  эмбеддеру можно позаимствовать из memohood. **Гейт:** карточек/узлов очень много И зонирование не
  справилось.
- **Зонирование графа** — `subgraph(point, depth=N)`: первый ответ на большой граф, чистый обход,
  без БД и векторов. Пробуем это раньше, чем вектора.
- **Нарезка больших файлов** — лок. агент ~65K токенов комфортно, ~100K предел. Ветка в скиле +
  программная нарезка → обработка сабагентами по кускам → сведение.
- **Диаграмма проекта для оператора** — визуальная схема из карты для архитектурных решений.
- **Тест-карты** — маппинг покрытия тестами; возможен спец-формат карточек для тестов. Отдельный разговор.
- **API-surface diff** (по git) — «было vs стало» у карточки; оправдан только когда карта огромная.
- **Циклы `A→B→C→A`** — graph-health, детекция циклических зависимостей.

**Принцип гейта:** каждая FUTURE-фаза добавляет сложность → берём её, только когда реальный проект
показал, что дешёвого NOW-слоя не хватило. Не строим впрок.
