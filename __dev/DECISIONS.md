# DECISIONS — решённые калы по РАЗРАБОТКЕ шаблона ProjectStarter

> Это НЕ шаблонный `__HQ/DECISIONS.md` (тот — пустой скаффолд для downstream-проектов). Здесь —
> закрытые решения про **сам продукт** (скелет ProjectStarter). Одна строка = решение + почему.
> Читать перед тем как что-то менять фундаментально; не релитигировать.

- **`HowTo__*` ≠ `Guide__*`.** `Guide__*` — рецепты авторинга **артефактов самой схемы** (Plan/Task/
  Context): generic, едут со скелетом. `HowTo__*` — **сервисные действия конкретного проекта** (run/
  test/build + «как писать программы этого проекта», напр. харнес): копятся per-project, линкуются из
  `START`. Почему: разделяет generic-схему и проектные сервис-доки. Следствие: пустой generic
  `HowTo__Write.md` без предмета удалён — предмет появляется только в проекте.
- **Рабочие файлы разработки шаблона живут в `__dev/`, не в `__HQ/`** — `__HQ/` это шаблон-продукт,
  копируемый в чужие проекты чистым; наши decisions/tracker/plans/vision его бы засорили. Bootstrap
  копирует продукт (`__HQ/`, `__map/`, программы), `__dev/` пропускает. `__dev` — та же `__`-семья
  мета-каталогов, что `__HQ`/`__map` (см. решение о `__`-маркере ниже), но отдельный каталог для
  работы НАД шаблоном.
- **`__`-префикс = маркер мета-слоя.** Все «наши», НЕ-исходные каталоги верхнего уровня: `__HQ`
  (мозг), `__map` (данные карты), `__dev` (разработка шаблона). Почему: живой исходник почти никогда
  не делает `__`-папки (дандер — это файлы `__init__`), так что `__` = безошибочный сигнал «это
  управлялка, не код проекта», и всплывает вверх в сортировке. Проверено ВСЛЕПУЮ на 3 холодных ЛЛМ:
  `__HQ`→«штаб/мозг», `__map`→«сводки файлов для контекста, читать вместо кода» — консенсус.
- **`__HQ` = мозг, `__map` = чистые данные карты.** `__HQ/` держит ВСЁ мета: управление
  (decisions/plans/roles/guides/vision/docs) + скилы (как `Guide`) + тулы (`__HQ/tools/`). `__map/` —
  только карточки, ПЛОСКО (`__map/<src-rel>.py.md`, без подпапки `cards/`). Карточка ≈ `.h` для
  исходника: интерфейс/сводка, читаешь вместо реализации. Почему: код и его выхлоп-данные разделяют
  по природе.
- **Тип `Skill` упразднён → всё `Guide`.** «Скил» корректно = LoRA НА модель (модель научили); у нас
  это документы, которые сильная модель RTFM'нет и исполнит. Папка `skills/` удалена; `Skill` не был
  даже в таксономии тегов.
- **`helpers/` → `tools/`** — точнее по смыслу (исполняемые инструменты).
- **Идентичность путей карточек.** Карточка адресуется путём относительно КОРНЯ проекта (+ расширение
  исходника, `db.py.md`); физическое место каталога карт (`__map/`) — КОНФИГ, не идентичность.
  Role/Guide сообщает корень сабагенту; тулы берут корень аргументом (`--cards-dir/--project-root`).
  Почему: переезд/переименование каталога карт не трогает содержимое карточек; снимает неоднозначность
  одинаковых имён файлов в разных папках.
