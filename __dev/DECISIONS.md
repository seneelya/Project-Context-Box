# DECISIONS — решённые калы по РАЗРАБОТКЕ шаблона ProjectStarter

> Это НЕ шаблонный `__HQ/DECISIONS.md` (тот — пустой скаффолд для downstream-проектов). Здесь —
> закрытые решения про **сам продукт** (скелет ProjectStarter). Одна строка = решение + почему.
> Читать перед тем как что-то менять фундаментально; не релитигировать.

- **`HowTo__*` ≠ `Guide__*`.** `Guide__*` — рецепты авторинга **артефактов самой схемы** (Plan/Task/
  Context): generic, едут со скелетом. `HowTo__*` — **сервисные действия конкретного проекта** (run/
  test/build + «как писать программы этого проекта», напр. харнес): копятся per-project, линкуются из
  `START`. Почему: разделяет generic-схему и проектные сервис-доки. Следствие: пустой generic
  `HowTo__Write.md` без предмета удалён — предмет появляется только в проекте.
- **Рабочие файлы разработки шаблона живут в `__dev/`, не в `__HQ/`** — `__HQ/` это шаблон-продукт,
  копируемый в чужие проекты чистым; наши decisions/tracker/plans/vision его бы засорили. Bootstrap
  копирует продукт (`__HQ/`, `__map/`, программы), `__dev/` пропускает. `__dev` — та же `__`-семья
  мета-каталогов, что `__HQ`/`__map` (см. решение о `__`-маркере ниже), но отдельный каталог для
  работы НАД шаблоном.
- **`__`-префикс = маркер мета-слоя.** Все «наши», НЕ-исходные каталоги верхнего уровня: `__HQ`
  (мозг), `__map` (данные карты), `__dev` (разработка шаблона). Почему: живой исходник почти никогда
  не делает `__`-папки (дандер — это файлы `__init__`), так что `__` = безошибочный сигнал «это
  управлялка, не код проекта», и всплывает вверх в сортировке. Проверено ВСЛЕПУЮ на 3 холодных ЛЛМ:
  `__HQ`→«штаб/мозг», `__map`→«сводки файлов для контекста, читать вместо кода» — консенсус.
- **`__HQ` = мозг, `__map` = чистые данные карты.** `__HQ/` держит ВСЁ мета: управление
  (decisions/plans/roles/guides/vision/docs) + скилы (как `Guide`) + тулы (`__HQ/tools/`). `__map/` —
  только карточки, ПЛОСКО (`__map/<src-rel>.py.md`, без подпапки `cards/`). Карточка ≈ `.h` для
  исходника: интерфейс/сводка, читаешь вместо реализации. Почему: код и его выхлоп-данные разделяют
  по природе.
- **Тип `Skill` упразднён → всё `Guide`.** «Скил» корректно = LoRA НА модель (модель научили); у нас
  это документы, которые сильная модель RTFM'нет и исполнит. Папка `skills/` удалена; `Skill` не был
  даже в таксономии тегов.
- **`helpers/` → `tools/`** — точнее по смыслу (исполняемые инструменты).
- **Идентичность путей карточек.** Карточка адресуется путём относительно КОРНЯ проекта (+ расширение
  исходника, `db.py.md`); физическое место каталога карт (`__map/`) — КОНФИГ, не идентичность.
  Role/Guide сообщает корень сабагенту; тулы берут корень аргументом (`--cards-dir/--project-root`).
  Почему: переезд/переименование каталога карт не трогает содержимое карточек; снимает неоднозначность
  одинаковых имён файлов в разных папках.
- **Два вложенных репо: тулы = свой git внутри репо шаблона («git в гите»).** `__HQ/tools/` — это
  **отдельный независимый git** (свой `.git`, ветка `master`, полная история), физически лежащий
  внутри дерева ProjectStarter. ProjectStarter его **игнорит** (`/__HQ/tools/` в своём `.gitignore`),
  поэтому это НЕ submodule (никакого gitlink/пиннинга коммита) — просто две отдельные репы,
  колокейтнутые для удобства разработки. Модель распространения = **копирование папки** (у проекта
  пока нет GitHub-репо), так что тулы физически едут со скелетом несмотря на игнор.
  - **Тулы чуть отдельно от общих скилов.** Общие `Guide__*`/роли/vision живут в git ProjectStarter;
    сами исполняемые тулы — в своём git `__HQ/tools/`. Референс-заметки по тулам разнесены осознанно:
    стабильные (`Vision01__*`, `HowTo__Test-*`) → `__dev/tools/` (git PS); живые (`TRACKER`,
    `DECISIONS`, `RESTORE`) → `__HQ/tools/__delme/` (git тулов, сносится при деплое).
  - ⚠️ **НЕ ЗАБЫВАТЬ КОММИТИТЬ В ОБА РЕПО.** Правка, задевающая и тул, и общий скил/док — это ДВА
    коммита в двух `.git`: один в `__HQ/tools/`, один в корне ProjectStarter. `git status` в корне
    PS вложенный репо не покажет (игнор) — проверять каждый отдельно.
  Почему: тулы версионируются как самостоятельный артефакт (своя история/ветки), но лежат рядом для
  удобства; цена — ручная синхронизация двух коммитов. Развилку submodule отклонили: связь через
  gitlink = дрейф указателя, не нужна независимость.
- **Деплой шаблона в проект — только через `__dev/deploy_hq.py`; git-история = базлайн.** Ручную
  сверку файлов выкинули. Тул копирует ТОЛЬКО шаблонный класс (root `START/CONTEXT_RESTORE/AGENTS`,
  `__HQ/WORKFLOW.md` + `Role__*` + `guides/**` + `tools/**` минус `.git/__delme/__pycache__/test/*.tmp`);
  проектный класс (`DECISIONS/TRACKER/HowTo__*/plans/vision/docs`) определён по ОМИССИИ — не трогается.
  Дрейф детектится без файла-состояния в проекте: «известные версии файла» = все его blob-id из
  git-истории владеющей репы (`tools/**` → вложенная tools-репа, остальное → репа ProjectStarter).
  Решение по файлу: нет в проекте→NEW; `ph==шаблон`→UPTODATE; `ph` ∈ известные (старая, но не правленая
  версия)→UPDATE-перезапись; `ph` не встречается нигде→CONFLICT (проект правил)→ручной мёрж/`--force`.
  Дефолт — dry-run; `--apply` пишет; undo = git самого проекта. **`CONFIG__TOOLS.py` — проектный**
  (конфиг PROJECT_ROOT/LANGUAGE/DECL_BACKEND): деплоем не трогается, на `--init` сеется как скаффолд.
  Почему: онбординг существующего проекта работает без «засева» — старые тулы узнаются по истории и
  спокойно обновляются, а реальную правку проекта видно как CONFLICT, а не молчком затирается.
- **Всё наше — внутри `__HQ/`, снаружи ничего (2026-09-29, Vision08).** `START.md`,
  `CONTEXT_RESTORE.md`, карточки (`__HQ/__map/`) переехали в штаб; `AGENTS.md`-мост упразднён, и
  опционального моста в корне тоже НЕТ — «везде один путь», так безопаснее. Почему: в чужом проекте
  (форк) штаб скрывается одной строкой `/__HQ/` и держит своё знание в своём git; агент стартует вне
  проекта и открывает `…/__HQ/START.md` по полному пути. ПЕРЕСМАТРИВАЕТ решение «`__map` —
  верхнеуровневый каталог рядом с `__HQ`» выше: `__map` — данные штаба (`CONFIG__TOOLS.MAP_DIR`, от
  HQ); легаси-раскладка (корневой `__map`, конфиг схемы 1) остаётся рабочей.
- **`__HQ/…` в доках = папка штаба (2026-09-29).** Не относительный от cwd путь, а имя штаба; команды
  пишутся `python __HQ/tools/<tool>.py`, стоя в другом месте — подставить реальный путь штаба.
  Абсолютные пути в `START.md` НЕ пишем: он template-owned (перезаписывается деплоем); штаб агент
  знает по пути, которым открыл `START.md`, исходники — `PROJECT_ROOT` в конфиге.
- **Планы и вижены ТУЛОВ — в `__HQ/tools/__dev/` (2026-09-30, решение владельца).** Всё, что меняет
  только тулы (штемпель, граф, get_codeblock …), ведётся в `__dev` tools-репо (`vision/`, `plans/`,
  `TRACKER.md`); здесь, в `__dev` шаблона, — раскладка штаба, деплой, роли/гайды. Нумерация
  Vision/Plan общая на оба репо. Vision09 перенесён туда, Plan08 родился там.
- **Язык подключается ЗАПИСЬЮ в реестр, не веткой `if` (2026-09-30, решение владельца).** Штемпель —
  `stamp_langs/` (контракт `stamp_langs/CONTRACT.md`), связи — реестры `find_code_usage`
  handlers/resolvers; CLI и отчёты тоже спрашивают реестр, а не держат свою таблицу расширений.
